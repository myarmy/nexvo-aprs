Thank you for reviewing the earlier request. I am reapplying with the concrete controls requested by the administrator.

Nexvo APRS is a non-commercial Android application for licensed amateur-radio operators. RepeaterBook data will be used only for an on-demand nearby-repeater list and map. The application will not mirror, bulk-download, redistribute, export, sell, or expose RepeaterBook data through the Nexvo server or another API.

REQUEST LIMIT
The RepeaterBook-enabled release will enforce a maximum of one RepeaterBook request per device/user every 60 seconds, with no burst allowance. Manual refresh cannot bypass the limiter or an active cooldown. The feature will not be released until these controls have passed device tests.

CACHE AND DUPLICATES
Successful responses are cached locally in the Android application sandbox for 24 hours. Requests with the same normalized country, coordinates, radius, and filter parameters use the cached response during that period. Identical concurrent requests are coalesced into one in-flight request; they do not create additional API calls.

EXPECTED VOLUME
The initial test has fewer than 10 users and is expected to generate fewer than 100 total requests per day (normally no more than 10 lookups per active user/day). The initial public-test ceiling is 100 users and 1,000 requests/day. Distribution will be paused and RepeaterBook will be contacted before this ceiling is exceeded.

GEOGRAPHIC / RESULT SCOPE
The initial release is restricted to Türkiye (TR). Each query is centered on the user's current or explicitly selected position, with a maximum radius of 200 km and a maximum of 250 returned/displayed repeater records. There is no country-wide download, grid scan, background crawler, database synchronization, or unattended polling.

HTTP 429 / BACKOFF
The client honors Retry-After. If it is absent, it applies exponential cooldowns of 60, 120, and 240 seconds plus 0–20% random jitter. Automatic retries stop after three attempts. During cooldown, duplicate and manual requests are blocked. Authentication/authorization 4xx responses are not retried.

TOKEN SECURITY
Each user supplies and uses their own RepeaterBook token. The RepeaterBook-enabled Android release will encrypt the token with AES/GCM using a non-exportable key generated by AndroidKeyStore. The implementation is already present in the application source, and the earlier device-ID-derived fallback has been removed. There is no plaintext or device-derived fallback; if Android Keystore is unavailable, the token is not stored and the feature remains disabled. Tokens are not sent to the Nexvo server and are excluded from logs, analytics, crash reports, APK resources, and source control.

ATTRIBUTION / NO REDISTRIBUTION
Every RepeaterBook-derived screen will display “Data © RepeaterBook — repeaterbook.com” with a working link back to RepeaterBook and a visible last-updated time. Cached data remains private to the app sandbox. The app provides no CSV/JSON export and no redistribution or proxy endpoint.
